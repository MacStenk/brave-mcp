# Contributing

Issues are the right first stop: describe what you expected, what happened, and
which Brave/Node versions you ran. For larger changes, open an issue before
writing code. German or English — both are fine.

If your change is visible to someone using the tools (a new parameter, a changed
result field, a fixed behaviour), add a line under `## [Unreleased]` in
[CHANGELOG.md](CHANGELOG.md) in the same pull request: what changed, then why it
matters. [RELEASES.md](RELEASES.md) says which changes count as breaking.

The README's "Grenzen" section lists known gaps with their own follow-up tasks;
those are good places to start.
